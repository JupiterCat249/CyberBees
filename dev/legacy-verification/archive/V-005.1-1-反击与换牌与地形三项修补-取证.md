## 二、问题①：反击（G-24）

### 根因（取证）
`scenes/battle/battle_combat.gd` 原 `attack()`：
```gdscript
var dmg := maxi(0, final_atk(aid) - final_reduce(tid))
units[tid]["hp"] = int(units[tid]["hp"]) - dmg          # ← 先扣主伤
...
if int(units[tid]["hp"]) > 0 and 距离 <= final_range(tid):   # ← 目标已死（hp<=0）→ 反击被整段跳过 ✗
```
且与 a500「同时计算」不符（实际是"先主伤后反击"）。

### 修正后
```gdscript
var cdmg := 0
if final_atk(tid) > 0 and 距离 <= final_range(tid):   # 条件只剩 a500 的两条
    cdmg = maxi(0, final_atk(tid) - final_reduce(aid))
    units[aid]["hp"] = int(units[aid]["hp"]) - cdmg    # ① 先算反击（守方按攻击前状态结算）
units[tid]["hp"] = int(units[tid]["hp"]) - dmg         # ② 再结算主伤害
# 日志顺序仍为「攻击 → 反击」（阅读顺序与数值结算顺序解耦）
```

### 实测（`game_eval`，一击必死场景）
```
攻方 熊蜂 atk=5 hp8；守方 熊蜂 hp=3（必然被一击打死）
→ 结算结果：攻方 hp 8→3（反击 -5）；守方 hp 3→-2（主伤 -5）存活=false
→ countered=true  counter=5   结算后单位数=3（守方已阵亡）
```
✅ **目标被打死，反击依然造成满额伤害**（原实现下攻方应保持 8）

### 另测（守方存活，防回归）
见 `V-005.1-2`：守方 hp 100 被 -5；攻方 hp 8 被反击 -5 → 双方都掉血，行为与修补前一致 ✅

## 三、问题②：移除换牌（G-25）

### 关键发现（本轮最有价值的定位）
换牌有**两个入口**，只改一个会留下漏洞：
1. `battle_deck.select_hand()` —— 准备阶段"只做选中，供换牌用"；
2. **`battle_state.on_hand_clicked()` —— 准备阶段自行处理"持牌/取消"**（**真实入口**，此前容易漏看）。

### 改动
| 文件 | 改动 |
|------|------|
| `battle_state.gd` | `on_hand_clicked` 准备阶段**直接 return**；删除 `exchange_hand` / `can_exchange` / `var exchange_left` |
| `battle_deck.gd` | 删除 `exchange_hand` / `can_exchange`（仅留说明注释）；`select_hand` 准备阶段 return |
| `battle_turn.gd` | 主按钮准备阶段只剩 `s.start_battle()`（去掉换牌分支） |
| `battle_setup.gd` | 不再初始化换牌次数；日志改为「对战准备：初始手牌已锁定（无换牌）…」 |
| `battle_hud_view.gd` | 主按钮文案不再有「换牌」；提示改为「对战准备：初始手牌已锁定（无换牌）—— 点主按钮「开始对局」进入第一回合」 |
| `battle_defs.gd` | 删除 `EXCHANGE_MAX` 常量 |

### 实测（真实鼠标点手牌 + `game_eval` 读数）
```
【改点1】准备阶段点手牌后：phase=4(准备) armed_card=-1(应-1) armed_side=[] mode=0(IDLE) 手牌=4
末行日志=对战准备：初始手牌已锁定（无换牌），点主按钮「开始对局」进入第一回合
```
✅ 点手牌**不选中、不进模式**；主按钮仍为「开始对局」

**截图复核**（`V-005.1-1-图-准备阶段无换牌.png`）：顶栏 `第1回合 · 阶段:准备 · 绿方 · 对战准备：初始手牌已锁定（无换牌）—— 点主按钮「开始对局」进入第一回合`；
主按钮 **`开始对局`**；双方手牌为普通态（**无选中高亮**）✅

**残留检查**：`grep -n "EXCHANGE_MAX\|exchange_left\|exchange_hand\|can_exchange" scenes/` → 仅剩说明性注释，**无任何可调用实现** ✅
