## 二、修复（走 MCP · 一处）

`resolve_targets(t, ctx)` **本来就持有 `ctx`**（其中含 `source_id`，见 `run_skill` 的 ctx 约定）✅，
只是在匹配时从 `t` 里读 `_source_id` 而无人写入 ✗。故在函数入口注入：

```gdscript
	var sid := int(ctx.get("source_id", -1))
	# 把施放者 id 注入 targets 的**副本**，供 _match_unit 的 range / exclude_source 使用
	# （此前全项目无写入点 → 两者恒失效）
	# 用副本而非直接改 t：避免污染共享的技能表常量（SKILLS）
	if not t.has("_source_id"):
		t = t.duplicate()
		t["_source_id"] = sid
```

**关键取舍**：用 `t.duplicate()` 而非直接改 `t` —— `t` 来自 `D.SKILLS` 常量，
直接写入会**永久污染技能表**（跨局积累、且是共享引用）✗；副本既让过滤生效又无副作用 ✅
