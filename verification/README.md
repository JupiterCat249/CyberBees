# verification/ —— 验证产物专区（非生产文件）

> 状态：**验证用目录，不属于生产/工程文件**
> 建立：2026-08-27（迭代003.1 起，人明确要求）
> 最后更新：2026-08-27

## 为什么存在

迭代过程中会产生大量**只用于验证**的内容（临时验证脚本、构造的测试单位/卡牌、
eval 取证脚本、截图与日志片段）。这些内容若混在 `scenes/` `assets/` 等生产目录中，
会与正式生产文件混淆、污染工程结构。

## 约定

1. **目录**：本目录（游戏仓根 `verification/`）为验证产物**唯一存放处**；
   已完成验证的产物放入 `verification/archive/`。
2. **命名**：`V-<迭代>-<检查点>-<简述>.<ext>`，例如
   `V-003.1-6-单位过滤-取证.md`、`V-003.1-6-过滤验证.gd`。
3. **标记**（每个文件头部必须标注）：
   ```
   > 状态：已封存（验证用，非生产文件）
   > 对应迭代/检查点：
   > 封存日期：YYYY-MM-DD
   ```
4. **隔离铁律**：生产代码**禁止**引用本目录（不得出现 `preload("res://verification/...")`
   或 `load("res://verification/...")`）；验证脚本可引用生产代码，反向不可。
5. **验证数据**：构造的测试单位/卡牌一律运行时生成，**不写入**生产场景或资源文件。
6. **封存时机**：每个检查点验证通过后**立即**封存并标记，纳入该检查点的 commit。

## 与工程导出的关系

本目录内容**不参与游戏导出**（Godot 导出时按过滤器排除）；仅作可追溯的验证记录。
