## 二、⚠️ 发现的缺陷：**对局未自动开始**（待查）

同一次运行的运行时读值：

```
started=false  phase=0   手牌: 绿=0 红=0   单位=0   费用={green:0, red:0}   地图=（空）
```

即：**`_prepare` 未执行** → 手牌 0 张、无蜂王、无地图 → 画面上的两侧卡牌面板是空的（截图中可见）✗

### 已知的调用链

| 环节 | 事实 |
|------|------|
| `battle_flow.gd:28` | `_ready()` |
| `battle_flow.gd:183` | **`state.start()`**（`_ready` 最后一行）✅ 调用点存在 |
| `battle_state.gd:81` | `func start(): if setup != null: setup.start()`（转发）|
| `battle_setup.gd` | `start()` → `if s.started: return` → `s.started = true` → `prepare()` |

**推论**：`started=false` 只能是 `setup` 为空（转发无操作）或 `start()` 之前 `_ready` 已中断。
已知**本轮之前**确有中断源：`turn_color` 崩溃发生在 `refresh()` 内、栈顶为 `battle_flow.gd:184 @ _ready()`
即**正在 `state.start()` 内** ✗ —— 该崩溃**已在本轮修复**（V-004-9）✅，
但**修复后重启的实例仍是 `started=false`** →

**结论**：**仍未定位**（`setup` 注入是否成功 / 是否有第二个中断源未查），标记为**待查缺陷** ⚠️

### 下一轮定位步骤（明确、可执行）

1. 重启游戏，**只读** eval：`state.setup != null`、`state.grid/pending/deck/deploy/action/victory/turn/interaction != null`（逐个点名，找出为空的）
2. 若某个为空 → 检查 `battle_flow` 中该注入块的位置是否在 `_ready` 内、以及其前的注入是否抛错
3. 若全部非空 → 在 `state.start()` 前后各打一条日志（临时），确认是否被执行
4. 修复后**必须**：重启 → 读 `started=true / phase=4(准备) / 手牌各 4 张 / 单位 2`（蜂王）才算通过
