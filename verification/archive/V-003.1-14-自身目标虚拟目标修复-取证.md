## 缺陷 D（真实缺陷）

`resolve_targets()` 的 `mode == "self"` 分支要求 `source_id >= 0`（施放者单位），
而**指令卡没有施放者单位** → 目标列表为空 → 「技能未生效：无有效目标」✗
→ **补给 / 轮换这类"作用于玩家自身"的指令卡完全不可用**。

## 修复

```gdscript
"self":
    if sid >= 0 and state.units.has(sid):
        out.append(state.units[sid]["cell"])
    else:
        # 指令卡没有施放者单位，但"作用于玩家自身"的效果（资源/手牌/部署）仍需结算
        # -> 返回虚拟目标格（不指向任何单位），依赖单位的伤害/增益类效果会自行拒绝
        out.append(Vector2i(-1, -1))
```
安全性：`Vector2i(-1,-1)` 不指向任何单位（`unit_at()` 返回 -1），
`apply_effect` 中依赖单位的伤害/增益分支均以 `id < 0` 拒绝，资源/手牌/部署类使用 `ctx.side` 不受影响。

## 关于"缺陷 E"的更正（重要）

原记录称"同一技能内多效果只结算第一个（回收的 +2 未生效）"——**为误判**：
测试把费用设为 **10（= 上限）**，回收的 `+2` 被 `clampi(0, COST_MAX)` **正确截断**，
故 `10 - 2(卡费) = 8` 是**符合 a500 费用上限的正确行为**。
→ **多效果路径本身没有问题**；教训是**测试要避开上限/边界值**，否则会把正确行为误判为缺陷。
