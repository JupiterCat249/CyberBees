# V-003.1-2 支援技能「直接点友方」路径 · 验证取证

> 状态：已封存（验证用，非生产文件）
> 对应迭代·检查点：迭代003.1 · 检查点 1/2（支援源交互路径修复）
> 封存日期：2026-08-27

## 现象

人反馈：支援技能**始终走不到确认环节**，也不会结束单位本回合行动。

## 取证与根因

代码本身无缺陷（已逐项核实）：
- 高亮 `ColorRect` 为 `MOUSE_FILTER_IGNORE`，不吃点击；
- 输入层按下/抬起与长按（帧数）处理正常；
- `SUPPORT_TARGET` 分支、二次确认 `confirm()`、`support_at()` 管线均正确。

**真因是交互路径缺一条**：玩家自然操作是「选中单位 → 直接点友方目标」，
而该路径在 `on_cell_clicked()` 中落入「点其他己方单位 = **改选**」分支 →
选择被切到目标单位，永远进不了支援确认。必须先「再点自身」进支援模式才行（不可发现）。

## 修复

新增 `can_support_at(cell)`：所选单位**有支援技能且未行动**、目标为**己方且在自己射程内** →
「直接点友方」也走 `confirm("支援", cell)` → 待确认 → 再点执行 → `support_at()` → `acted=true`。
「再点自身」进显式支援模式仍保留（两条路径并存，均不可发现性问题已消除）。

## 验证结果（实机 eval）

| 步骤 | 结果 |
|------|------|
| 启动接线自检 | 通过（7 项） |
| 选中叶蜂（未进支援模式） | `mode=0` |
| `can_support_at(友方格)` | `true` |
| ① 直接点友方 | `pending=支援` ← 到达确认环节 |
| ② 再点同格 | 泥蜂 `effects=["atk_up"]`、攻击 3→4；叶蜂 `acted=true`（结束本回合行动） |
| 日志 | `泥蜂 获得效果「攻击提升」` / `技能「鼓舞」生效（命中 1 处）` / `叶蜂 支援 泥蜂` |

## 结论

支援技能两条路径均可用，且使用后正确结束该单位行动（a500 行动机会 4）。
