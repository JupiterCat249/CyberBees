# 迭代054 「打开 Battle_Scene 是空的」修复记录（验证用 · 非生产）

## 一、问题与真因

**人反馈**：「我在打开 Battle_Scene 后看到的是空的，没有任何内容物。」

**真因（两层）**：
1. `battle_scene.tscn` 是**继承自 battle_ui_alpha.tscn 的骨架**；
   单位卡与手牌**只在运行时创建** → 编辑器里 `Units` / `HandPanel*` 容器本就是空的。
2. 磁盘上的 `battle_scene.gd` 被**编辑器脚本缓冲反复回退**成 256 行旧版（无 `auto_start`、无 GameState 接线）
   → 连运行也没有内容。（本轮共发生 3 次：22:23 / 22:40 / 22:44）

## 二、修法（全程走 Godot MCP）

| # | 动作 | 说明 |
|---|---|---|
| 1 | **内容烤入场景** | `battle_scene.tscn` 直接含：<br>· `Battle/MapView/MapCells/Cell_0_0 … Cell_3_3`（16 格点击区）<br>· `Battle/MapView/Units/Unit_ally · Unit_enemy`（双方蜂王预览）<br>· `Battle/HandPanelLeft/HandLeft/EnemyHand_0..3`<br>· `Battle/HandPanelRight/HandRight/AllyHand_0..3` |
| 2 | **两个卡组件加 `@tool`** | `card_unit.gd` / `card_hand.gd` → 编辑器里也能绑定显示；<br>`_process`/`_gui_input` 加 `Engine.is_editor_hint()` 守卫 |
| 3 | **控制器改为「接手」已烤节点** | `_build_cells()` 按名字认领 16 个 Cell（缺失才补建）；<br>首个单位生成时清掉预览单位；运行时按真实数据重建手牌 → 预览不堆叠 |
| 4 | **写盘一律用 MCP `write_text`** | 返回 `diagnostics_status: checked`、0 错误（绕开编辑器脚本缓冲） |

## 三、修复过程中新捕获的 2 个真实缺陷

| # | 现象 | 真因 | 修法 |
|---|---|---|---|
| 1 | 棋盘变成 **32 格**（重复补建） | 「认领」判定用了 `get_script() != CELL_SCRIPT`，**脚本对象引用比较不可靠** → 判定失败，16 格全被补建一遍 | 改为**按节点名认领**（`Cell_x_y`），并补 `node.set_script()` + `set(cell)` |
| 2 | 运行到 `_refresh_all` 报 `previously freed` | `_spawn_unit_node` 清预览单位后，`_unit_nodes` 里留着**已释放的引用** → 后续 `queue_free()` 对 freed 实例调用 | 统一 `_live_unit_node(id)` 守卫（失效引用顺手清理）；预览只清一次（`_preview_cleared`） |

## 四、验证

- `scene_open(force_reload=true)` 从磁盘重载成功
- 编辑器内实测节点数：`Units=2` · `HandRight=4` · `HandLeft=4` · `MapCells=16`
- **编辑器 2D 视口截图**确认：双方手牌卡（各 4 张）与单位卡（各 1）均可见
- 回归：规则层 **76/0** · UI 端到端 **23/0** · 动画+详情区 **38/0**

## 五、注意事项

- 烤入的预览单元卡/手牌卡上的**数字为静态值**（不绑规则数据）；点选后详情区即显示真实数据。
- 若在编辑器里**改动了 battle_scene.tscn 的容器结构**（改名/删除 `Cell_x_y`、`HandLeft`、`HandRight`），
  控制器的认领逻辑会退化为补建 —— 请保持容器名与层级不变。
