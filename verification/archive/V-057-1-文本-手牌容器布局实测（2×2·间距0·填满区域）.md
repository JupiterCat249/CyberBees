## 二、根因与修法

| # | 根因（全在 AI 侧） | 修法 |
|---|---|---|
| R-1 | `HandLeft`/`HandRight` 是 GridContainer 但**从未写 `columns`** → 默认 1 列 | 场景内显式写 `columns = 2` |
| R-2 | 生成器给容器子节点写了 `layout_mode = 0` + `offset_*` → **手动定位模式**与容器布局打架 | `build_scene.gd` 的 `_append_hand` **不再写任何布局** |
| R-3 | 运行时 `node.position = col*(200+30)…` 对容器子节点无效 | 已随旧控制器移除 |

间距：人裁决为 **0**（手牌自动填充区域）；文档默认是 4，故**显式写 0** 以防被改回。

## 三、方法论教训（已写入记录）

⚠️ **编辑器 2D 视口截图当时显示的是"单列 + 30 节点旧版"** —— 那是编辑器 tab 的**陈旧内存状态**，
**不代表磁盘/运行时的真实布局**。判定布局问题应**读运行时实测数据**（容器尺寸 + 子节点矩形），
而不是相信编辑器视口截图。

## 四、机械化守卫
`verification/rule_check.gd` 已加入**容器契约守卫**（每次自检自动跑）：
- `HandLeft`/`HandRight` 必须 `columns >= 2`
- `h_separation` / `v_separation` 必须显式为 0
- 手牌子卡**不得**含 `layout_mode` / `offset_*`
- 弃用文件（旧控制器 / sample_deck）不得再现
